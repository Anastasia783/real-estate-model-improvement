## Улучшение модели прогнозирования стоимости недвижимости

### Цель проекта

Исследовать способы улучшения исходной модели прогнозирования стоимости недвижимости: подготовить дополнительные признаки, выполнить отбор признаков и подобрать гиперпараметры.
Для сохранения параметров, метрик, моделей и результатов экспериментов используются MLflow Tracking Server и Model Registry.
Основная метрика выбора модели — MAE. Дополнительно анализируются RMSE и R2. Результаты на валидационной и тестовой выборках рассматриваются отдельно.

### Среда выполнения

В связи с недоступностью учебной виртуальной машины проект выполнен локально на Windows.
Python-код запускается в виртуальном окружении. MLflow Tracking Server и PostgreSQL работают в Docker-контейнерах. Артефакты MLflow хранятся в S3-хранилище Yandex Cloud.
Команды ниже приведены для PowerShell и выполняются из корня репозитория.

### Структура проекта

Основной ноутбук: model_improvement.ipynb.

Инструкция запуска MLflow: mlflow_server/README.md.

### Подготовка Python-окружения

В проекте использовался Python 3.11.

Создание виртуального окружения:
python -m venv .venv-stage3

Активация в PowerShell: 
..venv-stage3\Scripts\Activate.ps1

Установка зависимостей:
python -m pip install -r requirements.txt

Корневой requirements.txt содержит зависимости для анализа данных, преобразования признаков, обучения моделей, подбора гиперпараметров и работы с MLflow.
Для выполнения ноутбука выберите в редакторе ядро Python из подготовленного виртуального окружения. 

### Запуск MLflow

Подготовьте файл mlflow_server/.env по шаблону mlflow_server/.env.example и заполните необходимые параметры доступа для MLflow и S3.

### Запуск сервисов:
docker compose --project-directory .\mlflow_server --env-file .\mlflow_server.env -f .\mlflow_server\compose.yaml up --build --wait --wait-timeout 180

Интерфейс MLflow доступен по адресу http://localhost:5000.


При работе Python-клиента адрес Tracking Server:
http://localhost:5000

Сервер настроен на прямой доступ клиентов к S3. Поэтому переменные доступа к хранилищу должны быть доступны Python-процессу.
Рабочие файлы .env, пароли и ключи доступа не должны публиковаться в репозитории.

### Этапы работы
Исходная модель
Готовая baseline-модель загружается из прошлого проекта. Скрипт регистрации пересчитывает тестовые метрики и сравнивает их с исходным отчётом, затем сохраняет модель  в MLflow.

### Исследовательский анализ данных
Выполнен анализ данных  для последующей работы с признаками.

Генерация признаков
Подготовлены преобразования средствами scikit-learn и дополнительные признаки с помощью AutoFeat. Для применения уже обученных преобразований используется FittedEnrichedTransformer. Е

Отбор признаков
Исследованы прямой и обратный отбор признаков. Сохранены история отбора, сравнения моделей и результаты анализа важности признаков.

Подбор гиперпараметров
Проведён поиск гиперпараметров с помощью Optuna. Сопоставлены TPE и RandomSampler: по 25 испытаний для каждого метода, всего 50.
Результаты испытаний передаются в MLflow через Callback. Сохранены таблицы испытаний и сравнение методов.
Итоговая модель выбрана по валидационной MAE, после чего проведена оценка на тестовой выборке.
